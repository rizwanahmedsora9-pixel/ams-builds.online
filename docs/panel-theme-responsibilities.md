# Panel and theme responsibilities

The admin panel is the CMS control surface and is not replaced by a public theme.
Content and menus are stored independently so a site can switch themes without
losing its pages. A theme defines the public site's presentation and declares
which customization settings and menu locations it supports.

| CMS / admin panel | Public theme |
|---|---|
| Authentication, roles, permissions, content editing, publishing, revisions and media storage | Page, post, home, archive, search and 404 templates |
| Page parent relationships, menu items and their destinations | Header, footer, primary navigation placement (top, side or other layout), and responsive behavior |
| Site identity, logo, menu assignment, and data values entered by an administrator | How identity and menu data are rendered; icons, font choices, typography and color palette |
| Validate and store uploaded theme packages; preview, activate, export and revert | Declare supported settings, menu locations, assets and compatibility |
| Expose and validate supported theme settings in the customizer | Define defaults and use those settings in templates/CSS |
| Generate URLs, content data, metadata, security headers and common output | Decide supported template layout and visuals, within the CMS template and CSP rules |

## Current implementation boundaries

- The engine provides the standard `primary` and `footer` menu data. Declaring
  a location does not by itself create a new arbitrary menu editor or data source.
- Page hierarchy/breadcrumb and child-page markup are currently generated by the
  CMS and injected into page content. A theme can style those classes; it cannot
  yet freely replace the hierarchy markup or reposition it through a dedicated
  breadcrumb helper. Templates can still provide other navigation of their own.
- Themes declare supported options; arbitrary colors, menus, icons or layouts
  cannot be changed in the panel unless the theme provides those controls.
- Security, sanitization, template helper availability and asset restrictions
  are enforced by the CMS. A theme cannot replace the static admin panel or run
  arbitrary server-side Python/PHP.
- The CSS/JS and inline icon examples are theme-owned, but the CMS may generate
  markup (including widget and page hierarchy output) that the theme styles.

`src/themes/example1/` is an optional learning theme derived from Ahmed Pro.
It demonstrates a top navigation, theme-defined header/footer, inline icon
symbols, a stylesheet, responsive behavior and declared settings. See its README
and `docs/theme-developer-guide.md` for package structure and development.
