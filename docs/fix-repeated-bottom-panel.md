# Fix: repeated bottom action panel on every admin page

**Status:** removed. Visual-only change; no template markup, routes, data or logic touched.

## What the panel actually was

It was **not** a separate "shortcuts panel" template. It was the **command palette
(⌘K) `<dialog>`** — the one that lists the shortcuts in two groups, **Create**
(New post / New page / Upload media) and **Go to** (All posts, All pages, Media
library, Comments, …) — being **painted inline in the page while closed**.

## Where it came from

The palette is injected **globally**, once per page, by the shared layout:

| Layer | File | Role |
|---|---|---|
| Injection point | `src/lib/ui.ts` → `layout()` | appends `${palette(c, prefs)}` after `<div class="shell">…</div>` on **every** admin page |
| Markup | `src/lib/ui.ts` → `palette()` | `<dialog id="palette" class="palette">` with the Create / Go to command groups |
| **Root cause** | `src/admin/assets/app.css` → `.palette { … }` | `display: flex; flex-direction: column;` was set on the dialog unconditionally |

## The actual bug (CSS specificity)

Browsers hide a closed dialog with a **user-agent** rule:

```css
dialog:not([open]) { display: none; }
```

A UA declaration is overridden by *any* author declaration, and `.palette` has
enough specificity to beat `dialog:not([open])`. So the unconditional
`display: flex` in the `.palette` class **re-displayed the closed dialog**, and
because it sits after `</main>` — after the real page content — the whole command
list rendered as an extra full-width flexbox panel at the bottom of the page.
Same markup order on every screen, hence "almost every administration page".

Verified with a CSS engine before the fix:

```
#palette (closed)  ->  computed display: flex   *** painted after content ***
groups inside     ->  Create | Go to
```

## The fix (`src/admin/assets/app.css`)

`display` is no longer declared on the closed dialog; the flex column is scoped
to the open state, and a defensive rule keeps the closed state hidden:

```css
.palette { width: …; max-height: …; padding: 0; …; }   /* no display here */
.palette:not([open]) { display: none; }                 /* never in page flow */
.palette[open] { display: flex; flex-direction: column; }  /* layout only when shown */
```

After the fix, on all six verified pages:

```
closed = none      open = flex
```

So the panel is gone, and ⌘K / Ctrl+K / the Search button still open the palette
with its intended column layout.

## Rule for future screens

Never give a `<dialog>` a `display` in its closed state. Scope the layout to
`[open]` (and keep the `:not([open]) { display: none }` guard). A class
selector always beats the browser's `dialog:not([open]) { display: none }`,
which turns a hidden dialog into a permanent block at the end of the page.
